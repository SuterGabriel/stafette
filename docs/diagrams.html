The model proposes actions. Code decides whether they're allowed.

Five views of the same system: which parts talk to each other, which rules the Policy Engine uses to check every proposal, how a change of doctor plays out, which services we need and what happens during a call. Each color stands for the same role everywhere: Gemini, Gradium, Twilio and previous practices, Policy Engine, Anna, new practice.

Decision logic of check(action, args)

The checks run from left to right. The first one that fails determines the result. Anything not listed is blocked.

Calls and documents run in parallel. If the pipeline finds a doctor without records, the agent proposes a new source itself; only Anna's yes restarts the loop.

View 5 · Phone part

One call, step by step

Same mechanics as gradium-ai/digigrad (Twilio, bridge, gradbot), with two differences: Stafette only makes outgoing calls, and every tool call in the conversation goes through the Policy Engine.
